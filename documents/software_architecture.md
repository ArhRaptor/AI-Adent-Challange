# Software Architecture

## Separation of Concerns

Each component should have a focused responsibility. Loading documents, chunking, embedding, storage, and retrieval are easier to change when they are not tangled together. In a learning project this principle should be visible in the code, not only mentioned in documentation. A clear implementation makes later debugging, comparison, and refactoring easier. The same idea becomes more important as the number of files, tools, and external integrations grows.
