# День 12 — Персонализация ассистента

## Цель

Добавить персонализацию поверх модели памяти AI-агента.

Агент должен:

- иметь профиль пользователя;
- учитывать стиль общения;
- учитывать предпочтительный формат ответа;
- учитывать уровень детализации;
- учитывать ограничения;
- автоматически подключать профиль к каждому запросу;
- поддерживать разные профили пользователей.

---

## Технологии

- Python
- Google Gemini API
- `google-genai`
- модель `gemini-3.5-flash-lite`
- JSON
- CLI-интерфейс

---

# Архитектура

В предыдущем задании память агента была разделена на три слоя:

```text
SHORT-TERM MEMORY
WORKING MEMORY
LONG-TERM MEMORY
```

Теперь поверх модели памяти добавлен профиль пользователя:

```text
                USER PROFILE
                     │
                     ↓
              PERSONALIZATION
                     │
                     ↓
        ┌────────────┼────────────┐
        ↓            ↓            ↓
   LONG-TERM      WORKING     SHORT-TERM
     MEMORY         MEMORY       MEMORY
        └────────────┼────────────┘
                     ↓
                   PROMPT
                     ↓
                   GEMINI
                     ↓
          Персонализированный ответ
```

Профиль отвечает за то, **как ассистент должен отвечать**, а память — за то, **какую информацию ассистент знает**.

---

# User Profile

Профили пользователей хранятся отдельно:

```text
profiles.json
```

Каждый профиль содержит настройки персонализации.

Например:

```json
{
  "name": "Начинающий разработчик",
  "style": "дружелюбный и обучающий",
  "format": "пошаговые объяснения с простыми примерами",
  "detail_level": "подробно",
  "constraints": [
    "не использовать сложные термины без объяснения",
    "код объяснять простыми словами"
  ]
}
```

Профиль автоматически добавляется в каждый запрос к модели.

Поэтому пользователю не требуется каждый раз писать:

```text
Объясняй подробно.
Используй простые слова.
Показывай примеры.
Я начинающий разработчик.
```

Эти требования уже находятся в профиле.

# Реализованные профили

Для демонстрации реализованы два разных профиля.

## Beginner

Профиль начинающего разработчика:

```json
{
  "name": "Начинающий разработчик",
  "style": "дружелюбный и обучающий",
  "format": "пошаговые объяснения с простыми примерами",
  "detail_level": "подробно",
  "constraints": [
    "не использовать сложные термины без объяснения",
    "код объяснять простыми словами"
  ]
}
```

Такой профиль должен получать:

- подробные ответы;
- простые объяснения;
- пошаговый формат;
- примеры;
- объяснение сложных терминов.

---

## Expert

Профиль опытного разработчика:

```json
{
  "name": "Опытный разработчик",
  "style": "технический и прямой",
  "format": "краткие технические ответы",
  "detail_level": "кратко",
  "constraints": [
    "не объяснять базовые понятия",
    "минимум вводного текста"
  ]
}
```

Такой профиль должен получать:

- короткие ответы;
- техническую терминологию;
- минимум базовых объяснений;
- минимум вводного текста.

# Подключение профиля к запросу

При каждом запросе агент получает текущий профиль:

```text
USER PROFILE
      +
LONG-TERM MEMORY
      +
WORKING MEMORY
      +
SHORT-TERM MEMORY
      +
USER MESSAGE
      ↓
    GEMINI
```

Таким образом, персонализация работает автоматически.

Метод `build_prompt()` добавляет профиль в контекст каждого запроса.

Упрощённо:

```text
ПРОФИЛЬ ПОЛЬЗОВАТЕЛЯ:
{
    style,
    format,
    detail_level,
    constraints
}

ДОЛГОВРЕМЕННАЯ ПАМЯТЬ:
...

РАБОЧАЯ ПАМЯТЬ:
...

КРАТКОСРОЧНАЯ ПАМЯТЬ:
...

Пользователь:
<новый вопрос>
```

# Профиль и память — разные сущности

Важно разделять персонализацию и память.

## Profile

Определяет:

```text
КАК отвечать?
```

Например:

```text
style = обучающий
detail_level = подробно
format = пошагово
```

## Long-Term Memory

Определяет:

```text
ЧТО агент постоянно знает?
```

Например:

```text
preferred_language = Kotlin
```

## Working Memory

Определяет:

```text
ЧТО важно для текущей задачи?
```

Например:

```text
project = Android-приложение для склада
```

## Short-Term Memory

Определяет:

```text
О ЧЁМ мы говорили только что?
```

Например:

```text
последние вопросы и ответы
```

Итоговая модель:

```text
PROFILE
→ как отвечать

LONG-TERM
→ постоянные данные

WORKING
→ текущая задача

SHORT-TERM
→ текущий разговор
```

# Тест персонализации

Для проверки используется одинаковый вопрос для разных профилей:

```text
Объясни, что такое Dependency Injection в Android.
```

Перед каждым тестом Short-Term Memory очищается, чтобы предыдущий ответ не влиял на следующий:

```text
clear short
```

---

# Тест 1 — Beginner

Выбираем:

```text
profile beginner
```

Задаём:

```text
Объясни, что такое Dependency Injection в Android.
```

Ожидаемое поведение:

```text
подробный ответ
+
простые слова
+
пошаговое объяснение
+
примеры
```

---

# Тест 2 — Expert

Очищаем текущий контекст:

```text
clear short
```

Переключаем профиль:

```text
profile expert
```

Задаём точно такой же вопрос:

```text
Объясни, что такое Dependency Injection в Android.
```

Ожидаемое поведение:

```text
короткий ответ
+
техническая терминология
+
минимум базовых объяснений
+
минимум вводного текста
```

Таким образом:

```text
               ОДИН ВОПРОС
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
      BEGINNER              EXPERT
          │                   │
       подробно             кратко
       пошагово           технически
       примеры            без базы
          │                   │
          └─────────┬─────────┘
                    ↓
             ОДНА МОДЕЛЬ GEMINI
```

Меняется не модель и не вопрос.

Меняется только профиль пользователя.

Это позволяет проверить влияние персонализации на ответы агента.

# Персонализация + память

Профиль можно использовать одновременно с моделью памяти из предыдущего задания.

Например, сохраняем долговременное предпочтение:

```text
remember long preferred_language=Kotlin
```

Сохраняем информацию текущей задачи:

```text
remember work project=Android-приложение для склада
```

После этого спрашиваем:

```text
Покажи пример Dependency Injection для нашего проекта.
```

Агент получает:

```text
PROFILE
→ как объяснять

LONG-TERM MEMORY
→ preferred_language = Kotlin

WORKING MEMORY
→ Android-приложение для склада

SHORT-TERM MEMORY
→ текущий разговор
```

В результате пользователю не требуется повторять:

```text
Покажи пример на Kotlin.
Мы делаем Android-приложение.
Объясняй мне как начинающему.
```

Агент получает эти данные автоматически.

# Хранение данных

В проекте используются отдельные JSON-файлы:

```text
short_term_memory.json
working_memory.json
long_term_memory.json
profiles.json
```

Назначение:

| Файл | Назначение |
|---|---|
| `short_term_memory.json` | текущий диалог |
| `working_memory.json` | данные текущей задачи |
| `long_term_memory.json` | долговременные данные |
| `profiles.json` | настройки персонализации |

# Вывод

Персонализация позволяет отделить знания агента от способа взаимодействия с пользователем.

```text
MEMORY
→ что агент знает

PROFILE
→ как агент должен отвечать
```

Один и тот же вопрос может получить разные ответы в зависимости от выбранного профиля пользователя.

При этом пользователю не требуется повторять свои предпочтения в каждом сообщении — профиль автоматически подключается к каждому запросу.

Это позволяет построить ассистента, который адаптируется под конкретного пользователя и сохраняет единый стиль взаимодействия на протяжении работы.
