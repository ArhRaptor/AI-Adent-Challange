# День 8 — Работа с токенами

## Задание

Добавить в код агента подсчёт токенов:

- для текущего запроса;
- для всей истории диалога;
- для ответа модели.

Сравнить:

- короткий диалог;
- длинный диалог;
- диалог, который превышает лимит модели.

Показать:

- как растёт количество токенов по мере увеличения диалога;
- что происходит при переполнении контекста.

## Используемые технологии

- Python
- Google Gemini API
- библиотека `google-genai`
- JSON для хранения истории диалога
- модель `gemini-3.6-flash`

## Реальные лимиты модели

При запуске агент получает информацию о модели через Gemini API.

В моём тесте модель показала:

```text
Модель:                gemini-3.6-flash
Лимит входа модели:    1048576
Лимит выхода модели:   65536
```

То есть реальный лимит входного контекста модели составляет:

```text
1 048 576 токенов
```

Для безопасной демонстрации переполнения в агент также добавлена
возможность установить собственный тестовый лимит.

Например:

```text
limit 2000
```

Важно: эта команда не изменяет настоящий лимит Gemini.

Она устанавливает локальное ограничение внутри агента, чтобы можно
было продемонстрировать переполнение контекста без необходимости
отправлять более миллиона токенов.

---

## Архитектура

Агент реализован отдельным классом:

```text
Пользователь
     ↓
CLI
     ↓
GeminiAgent
     ↓
История диалога
     ↓
Подсчёт токенов
     ↓
Проверка лимита
     ↓
Gemini API
     ↓
Ответ
     ↓
Сохранение истории
```

Класс `GeminiAgent` отвечает за:

- работу с Gemini API;
- загрузку истории;
- сохранение истории;
- формирование полного контекста;
- подсчёт токенов;
- проверку лимита;
- отправку запроса модели;
- получение статистики использования токенов.

---

## Подсчёт токенов

Для подсчёта используется метод Gemini API:

```python
result = self.client.models.count_tokens(
    model=self.model,
    contents=text
)

return result.total_tokens
```

Перед каждым запросом агент отдельно считает:

```text
Текущий запрос
История диалога
Весь вход в модель
```

Например:

```text
Текущий запрос:        12
История диалога:       1770
Весь вход в модель:    1792
```

Таким образом можно увидеть, что короткое новое сообщение может
занимать совсем немного токенов, но из-за накопленной истории
реальный запрос к модели становится значительно больше.

---

## Токены после ответа

После ответа Gemini используется:

```python
response.usage_metadata
```

Из него агент получает:

```python
usage.prompt_token_count
usage.candidates_token_count
usage.total_token_count
usage.thoughts_token_count
```

В консоли отображается:

```text
Входных токенов API
Токенов ответа
Thinking tokens
Всего токенов API
```

Пример из теста:

```text
Входных токенов API: 1792
Токенов ответа:      896
Thinking tokens:     963
Всего токенов API:   3651
```

## Команды агента

При запуске программа показывает подсказку:

```text
help         — показать подсказку
stats        — показать статистику токенов
clear        — очистить историю диалога
limit 500    — установить лимит 500 токенов
limit 1000   — установить лимит 1000 токенов
limit real   — вернуть реальный лимит модели
exit         — завершить программу
```

Также можно установить другое значение:

```text
limit 2000
```

# Эксперимент

## 1. Начало диалога

Перед началом теста история была пустой:

```text
Сообщений в истории: 0
Токенов в истории:   0
```

Первый запрос:

```text
Давай поговорим
```

Результат:

```text
Текущий запрос:        4
История диалога:       0
Весь вход в модель:    14
```

После ответа:

```text
Входных токенов API: 14
Токенов ответа:      103
Thinking tokens:     482
Всего токенов API:   599
```

На первом сообщении контекст практически пустой, поэтому количество
входных токенов очень маленькое.

---

## 2. Рост истории

Следующий вопрос:

```text
Как ты думаешь почему земля не плоская?
```

Перед отправкой:

```text
Текущий запрос:        11
История диалога:       117
Весь вход в модель:    138
```

После нескольких сообщений статистика стала:

```text
Сообщений в истории:   6
Токенов в истории:     1770
Реальный лимит модели: 1048576
```

Это показывает, что история постепенно увеличивается.

Каждый новый запрос содержит не только новое сообщение пользователя,
но и предыдущий диалог.

---

## 3. Установка тестового лимита

Для демонстрации переполнения был установлен тестовый лимит:

```text
limit 2000
```

После этого:

```text
Сообщений в истории:   6
Токенов в истории:     1770
Текущий лимит:         2000
Лимит заполнен:        88.50%
```

История уже занимала почти 90% установленного лимита.

---

## 4. Ещё один запрос

Был отправлен вопрос:

```text
Какая планета больше всего похожа на землю?
```

Перед отправкой:

```text
Текущий запрос:        12
История диалога:       1770
Весь вход в модель:    1792
Текущий лимит:         2000
Лимит заполнен:        89.60%
```

Запрос ещё помещался в лимит, поэтому был отправлен Gemini.

После ответа:

```text
Входных токенов API: 1792
Токенов ответа:      896
Thinking tokens:     963
Всего токенов API:   3651
```

После сохранения нового ответа история выросла до:

```text
Сообщений в истории:   8
Токенов в истории:     2687
Текущий лимит:         2000
Лимит заполнен:        134.35%
```

Таким образом история уже превысила установленный тестовый лимит.

---

# Переполнение контекста

После этого был отправлен ещё один запрос:

```text
продолжим разговор
```

Агент посчитал:

```text
Текущий запрос:        5
История диалога:       2687
Весь вход в модель:    2701
Текущий лимит:         2000
Лимит заполнен:        135.05%
```

После этого сработала защита:

```text
============================================================
КОНТЕКСТ ПЕРЕПОЛНЕН
============================================================

Количество токенов: 2701
Текущий лимит:      2000

Запрос НЕ отправлен в Gemini API.
```

Таким образом агент проверяет размер контекста до обращения к модели.

Если установленный лимит превышен, запрос блокируется.

---

## Очистка истории

Для освобождения контекста используется:

```text
clear
```

После выполнения:

```text
История очищена.
```

История снова становится пустой, и диалог можно начать заново.

Также тестовый лимит можно убрать командой:

```text
limit real
```

После этого агент снова использует настоящий лимит модели.

---

# Что показал эксперимент

По мере продолжения разговора история увеличивалась:

```text
0 токенов
↓
117 токенов
↓
948 токенов
↓
1770 токенов
↓
2687 токенов
```

При этом новые сообщения пользователя сами по себе были небольшими.

Например:

```text
Текущий запрос: 12 токенов
```

но полный запрос к модели составлял:

```text
1792 токена
```

Причина в том, что агент передаёт модели предыдущую историю диалога.

Получается:

```text
Новый запрос
+
История диалога
=
Полный контекст модели
```

Чем длиннее разговор, тем больше входных токенов необходимо
обрабатывать модели.

# Вывод

В ходе задания был реализован подсчёт токенов для:

- текущего сообщения пользователя;
- всей истории диалога;
- полного входного контекста;
- ответа модели;
- thinking tokens;
- общего количества токенов API.

Эксперимент показал, что количество токенов растёт вместе с историей
диалога.

Даже если пользователь отправляет короткое сообщение, агент передаёт
модели накопленный контекст, поэтому размер входного запроса может
быть значительно больше самого сообщения.

Также была реализована проверка переполнения контекста.

Для безопасной демонстрации использовался тестовый лимит в 2000
токенов. При размере полного контекста 2701 токен агент обнаружил
переполнение и не отправил запрос в Gemini API.

В реальном приложении бесконечно хранить и передавать всю историю
неэффективно. При росте контекста необходимо использовать такие
подходы, как:

- удаление старых сообщений;
- ограничение размера истории;
- суммаризация старого диалога;
- очистка истории;
- хранение только релевантного контекста.

## Результат

Создан агент, который:

- сохраняет историю между запусками;
- считает токены;
- показывает рост контекста;
- получает реальные лимиты модели;
- позволяет устанавливать тестовый лимит;
- обнаруживает переполнение;
- не отправляет слишком большой запрос в API;
- позволяет очищать историю и продолжать работу.
