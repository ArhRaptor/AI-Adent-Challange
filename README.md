# День 16 — Подключение MCP

## Цель

Познакомиться с MCP (Model Context Protocol) и реализовать минимальное взаимодействие между MCP-клиентом и MCP-сервером.

Необходимо:

- установить MCP SDK;
- создать локальный MCP-сервер;
- создать MCP-клиент;
- установить соединение;
- получить список доступных инструментов;
- вывести информацию об инструментах.

На этом этапе инструменты ещё не используются агентом — задача состоит именно в проверке MCP-соединения и механизма обнаружения инструментов.

---

# Что такое MCP

MCP — Model Context Protocol.

Это протокол, который позволяет AI-приложению взаимодействовать с внешними инструментами и источниками данных через стандартный интерфейс.

Упрощённая схема:

```text
AI / Application
       │
       ↓
   MCP Client
       │
       │ MCP
       ↓
   MCP Server
       │
       ↓
     Tools
```

MCP-клиенту не обязательно заранее знать внутреннюю реализацию каждого инструмента.

Он может подключиться к серверу и запросить:

```text
Какие инструменты доступны?
```

Сервер возвращает их описание.

# Архитектура проекта

В учебном примере используются два Python-файла:

```text
main.py
mcp_server.py
```

Их роли различаются.

```text
main.py
   │
   │ MCP Client
   │
   ↓
mcp_server.py
   │
   │ MCP Server
   │
   ├── add
   │
   └── greet
```

`mcp_server.py` предоставляет инструменты.

`main.py` подключается к серверу и получает список этих инструментов.

Для работы используется официальный MCP SDK для Python.

Установка:

```powershell
py -m pip install "mcp[cli]"
```

Проверить установленный пакет:

```powershell
py -m pip show mcp
```

# MCP Server

Для демонстрации создан локальный MCP-сервер:

```text
mcp_server.py
```

Сервер содержит два тестовых инструмента.

## add

Инструмент:

```text
add
```

принимает два числа и возвращает их сумму.

Например:

```text
a = 10
b = 5
```

Результат при будущем вызове инструмента:

```text
15
```

На Дне 16 сам вызов инструмента не является основной задачей — `add` нужен для проверки обнаружения tools.

---

## greet

Второй инструмент:

```text
greet
```

принимает имя пользователя и возвращает приветствие.

Например:

```text
name = Alex
```

может вернуть:

```text
Привет, Alex!
```

---

# Регистрация инструментов

Инструменты публикуются MCP-сервером через декоратор:

```python
@mcp.tool(...)
```

Таким образом сервер сообщает MCP-клиентам, какие действия он предоставляет.

Схематично:

```text
MCP SERVER

@mcp.tool
    ↓
   add

@mcp.tool
    ↓
  greet
```

# MCP Client

В:

```text
main.py
```

реализован MCP-клиент.

Его задача:

```text
запустить MCP Server
        ↓
установить соединение
        ↓
выполнить MCP handshake
        ↓
запросить список tools
        ↓
вывести tools
```

# Stdio transport

Для локального взаимодействия используется `stdio`.

Клиент получает параметры запуска сервера:

```python
StdioServerParameters(
    command="py",
    args=["mcp_server.py"]
)
```

То есть клиент знает, что локальный MCP-сервер можно запустить командой:

```powershell
py mcp_server.py
```

При использовании stdio-клиента сервер запускается как отдельный процесс, а обмен MCP-сообщениями происходит через стандартные потоки ввода/вывода.

# Установка соединения

Соединение создаётся внутри:

```python
async with Client(server) as client:
```

Внутри этого блока клиент может взаимодействовать с MCP-сервером.

После успешного подключения программа выводит:

```text
MCP-соединение установлено.
```

---

# Информация о сервере

После соединения клиент может получить информацию о подключённом сервере.

Например:

```text
Имя сервера
Версия сервера
Версия MCP-протокола
```

Это позволяет убедиться, что MCP handshake прошёл успешно.

---

# Получение списка инструментов

Главная операция Дня 16:

```python
result = await client.list_tools()
```

После этого:

```python
tools = result.tools
```

содержит инструменты, опубликованные MCP-сервером.

Схема:

```text
MCP CLIENT
     │
     │ list_tools()
     ↓
MCP SERVER
     │
     ↓
┌───────────┐
│    add    │
│   greet   │
└───────────┘
```

---

# Описание инструмента

Для каждого полученного инструмента клиент выводит:

```text
Name
Title
Description
Input schema
```

Например структура вывода может выглядеть так:

```text
TOOL #1

Name: add
Title: Calculator
Description: Складывает два числа.
Input schema: ...
```

и:

```text
TOOL #2

Name: greet
Title: Greeting
Description: Возвращает приветствие.
Input schema: ...
```

Точное содержимое схемы и служебных полей зависит от используемой версии MCP SDK.

---

# Input Schema

Особенно важное поле:

```text
input_schema
```

Оно описывает параметры, которые принимает инструмент.

Например инструмент:

```python
def add(a: int, b: int)
```

должен сообщить клиенту, что для его вызова нужны аргументы:

```text
a
b
```

и их типы.

Это важно для AI-агентов: модель или управляющий код может узнать не только название инструмента, но и какие данные необходимы для его вызова.

# Асинхронная работа

MCP-клиент использует асинхронный код:

```python
async def main():
```

Запуск выполняется через:

```python
anyio.run(main)
```

А получение инструментов:

```python
await client.list_tools()
```

Таким образом взаимодействие с MCP-сервером выполняется асинхронно.

# Что происходит внутри

Полный процесс выглядит так:

```text
START
  │
  ↓
main.py
  │
  │ создаёт MCP Client
  ↓
StdioServerParameters
  │
  │ запускает
  ↓
mcp_server.py
  │
  ↓
MCP Server
  │
  ↕
MCP handshake
  │
  ↓
Соединение установлено
  │
  ↓
client.list_tools()
  │
  ↓
MCP Server
  │
  ↓
add + greet
  │
  ↓
MCP Client
  │
  ↓
PRINT TOOLS
```

---

# Что пока НЕ реализовано

На этом этапе MCP-инструменты только обнаруживаются.

То есть реализовано:

```text
CONNECT
   ↓
LIST TOOLS
   ↓
PRINT TOOLS
```

Но пока нет:

```text
CALL TOOL
```

и нет:

```text
LLM
 ↓
выбор инструмента
 ↓
MCP
 ↓
выполнение инструмента
```

Это следующий уровень интеграции.

# Вывод

День 16 добавляет новый архитектурный уровень:

```text
LLM
 ↓
MCP Client
 ↓
MCP Server
 ↓
Tools
```

Главный результат этого этапа — клиент может подключиться к MCP-серверу и программно узнать, какие инструменты предоставляет сервер.

Следующий логический шаг:

```text
LIST TOOLS
    ↓
SELECT TOOL
    ↓
CALL TOOL
    ↓
GET RESULT
```

То есть перейти от обнаружения инструментов к их реальному вызову.
